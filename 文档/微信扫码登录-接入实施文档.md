# 微信扫码登录 · 接入实施文档

> 服务器、域名、SSL 证书已有，本文只解决一件事：**把微信扫码登录接进现有登录页**。

---

## 一、费用：只有 300 元/年

| 项目 | 费用 | 说明 |
|---|---|---|
| 开放平台开发者资质认证 | **300 元 / 年** | 唯一支出 |
| 扫码登录接口调用 | **免费** | 不按次计费，调用量再大也是 0 元 |

服务器、域名、SSL 已有，不产生额外费用。

**这 300 元不是花在调用上，是花在资格上。** 不做资质认证，账号创建不了「网站应用」，接口根本调不了。而且是年费，第二年要续，不续名下应用会失效。

### 时间：约 2 周

| 阶段 | 耗时 |
|---|---|
| 注册开放平台账号 | 当天 |
| 开发者资质认证 | 1–7 个工作日 |
| 网站应用审核 | 约 7 个工作日 |

域名已备案的话，这两段就是纯等审核，没有其他前置依赖。

---

## 二、前置条件

| 条件 | 要求 |
|---|---|
| 企业主体 | 需营业执照，个人开发者做不了 |
| 已备案域名 | 授权回调域必须是自己的已备案域名，**不能填 IP** |
| 可访问的官网页面 | 审核员会真的点开看 |

**特别注意：不能只有一个登录页。** 申请网站应用要填「应用官网」，审核员打开如果只看到一个登录框，会被判定"网站不完整"驳回。得有公司介绍、主营业务、联系方式这类内容，登录入口放在 `/login`。

---

## 三、开发登录页

保留原有账号密码登录，下方加一个「微信扫码登录」按钮，点击后打开弹窗。

```html
<div class="login">
  <h2>后台登录</h2>
  <input id="account" placeholder="账号">
  <input id="pwd" type="password" placeholder="密码">
  <button id="btnLogin">登录</button>

  <div class="or"><span>或</span></div>

  <button id="btnWx" class="wx-btn">微信扫码登录</button>
</div>

<div id="wxModal" class="modal" hidden>
  <div class="modal-box">
    <div class="modal-head">
      <b>微信扫码登录</b>
      <button id="btnClose">×</button>
    </div>
    <div id="wxQrBox"></div>
    <p class="tip">请使用微信扫一扫登录</p>
  </div>
</div>
```

### 尺寸规范

| 元素 | 尺寸 | 说明 |
|---|---|---|
| 弹窗宽度 | 380px | 二维码居中，左右各留 20px |
| 二维码容器 | 300 × 400 | 官方 iframe 固定这么大，写死即可 |
| 弹窗总高 | 约 500px | 标题 + 二维码 + 提示文案 |

```css
.modal{position:fixed;inset:0;background:rgba(0,0,0,.45);
  display:flex;align-items:center;justify-content:center;z-index:100}
.modal-box{width:380px;background:#fff;border-radius:12px;padding:16px 20px 24px;text-align:center}
#wxQrBox{width:300px;height:400px;margin:8px auto 0}
```

**注意：** 账号密码登录不要删。微信侧出问题时（认证到期、接口调整），它是唯一的后路。

## 四、点击弹出二维码，微信扫码登录

### 前端：渲染二维码

引入官方脚本，弹窗打开时实例化。**二维码不用自己生成。**

```html
<script src="https://res.wx.qq.com/connect/zh_CN/htmledition/js/wxLogin.js"></script>
<script>
const btnWx    = document.getElementById('btnWx');
const btnClose = document.getElementById('btnClose');
const wxModal  = document.getElementById('wxModal');
const wxQrBox  = document.getElementById('wxQrBox');

btnWx.onclick = async () => {
  wxModal.hidden = false;
  wxQrBox.innerHTML = '';                     // 每次打开都生成新码

  const { state } = await fetch('/api/wx/state').then(r => r.json());

  new WxLogin({
    id: 'wxQrBox',
    appid: '你的AppID',
    scope: 'snsapi_login',
    redirect_uri: encodeURIComponent('https://admin.yourdomain.com/api/wx/callback'),
    state,
    style: 'black',
    self_redirect: false                      // 确认后在父窗口跳转
  });
};

btnClose.onclick = () => { wxModal.hidden = true; wxQrBox.innerHTML = ''; };
</script>
```

### 后端：接回调，换 openid

用户在手机上点「确认登录」后，微信跳回 `redirect_uri`，带上 `code` 和 `state`。

```
GET /api/wx/callback?code=CODE&state=STATE
```

四步处理：

**① 校验 state** —— 从缓存取出并立即删除，取不到直接拒绝。

**② code 换身份**

```
GET https://api.weixin.qq.com/sns/oauth2/access_token
    ?appid=APPID&secret=SECRET&code=CODE&grant_type=authorization_code
```

返回 `openid`。`code` 只能用一次，5 分钟过期。

**③ 查绑定关系**

| 情况 | 处理 |
|---|---|
| openid 已绑定账号 | 直接发登录态 |
| openid 未绑定 | 跳绑定页，输手机号 + 验证码，绑定已有账号 |

**④ 写登录态，跳后台**

```
Set-Cookie: token=xxx; HttpOnly; Secure; SameSite=Lax; Max-Age=604800
```

### 必须处理的两个分支

- **二维码过期**：官方 iframe 自带「已失效 + 刷新」，不用自己开发。
- **未绑定用户**：这是唯一要自己设计的页面。**不要做成扫码即注册**，后台账号必须由管理员开通。

## 五、微信开放平台：从注册到拿到密钥

### 先说清楚：这不是「建平台」

「微信开放平台」是腾讯给开发者的管理后台（open.weixin.qq.com）。你要做的只是在里面注册一个账号、创建一个应用、拿到一对密钥。二维码、扫码页面全都不用你提供。

下面四步，每步都标了**目的**——知道为什么做，才不会在字段上填错。

### 阶段一 · 注册账号（目的：确认"你是谁"）

微信所有能力都绑定在主体上，没有账号什么都申请不了。

| # | 操作 | 目的 |
|---|---|---|
| 1 | 打开 `open.weixin.qq.com`，点「注册」 | 网站应用的唯一申请入口 |
| 2 | 主体类型选「企业」（个体工商户也可） | 只有企业主体能创建网站应用 |
| 3 | 填邮箱（未注册过公众号/小程序的）、设置密码 | 账号唯一标识 |
| 4 | 去邮箱点激活链接 | 验证邮箱真实可用 |
| 5 | 填企业名称、统一社会信用代码、法人姓名与身份证 | 主体实名 |
| 6 | 填管理员姓名、手机号、身份证 | 后续所有操作的操作人 |
| 7 | 提交 | 微信据此建立企业主体档案 |

**产出**：一个企业主体的开放平台账号。

**注意**：一个企业只能注册一个开放平台账号，旗下可挂多个应用；邮箱不能与已有公众号/小程序重复。

### 阶段二 · 开发者资质认证（目的：解锁接口权限）

**没认证的账号创建不了网站应用**，这是硬门槛，也是那 300 元的去处。

| # | 操作 | 目的 |
|---|---|---|
| 1 | 登录 → 账号中心 → 开发者资质认证 | 未认证无法创建网站应用 |
| 2 | 上传营业执照、填企业信息 | 主体核验 |
| 3 | 对公账户打款验证（微信打一笔随机小额，回填金额） | 证明对公账户确实属于你 |
| 4 | 缴 300 元认证费 | 微信收取的开发者资质年费 |
| 5 | 等审核，1–7 个工作日 | — |

**产出**：账号具备创建网站应用的资格。

**注意**：认证有效期 **1 年**，到期不续费名下应用会失效。

### 阶段三 · 创建网站应用（目的：拿到扫码登录的"身份证"）

这一步才是真正的"建应用"。网站应用就是扫码登录这个能力的载体。

| # | 字段 | 怎么填 | 为什么重要 |
|---|---|---|---|
| 1 | 应用名称 | 与实际业务一致 | 写"测试"必被驳回 |
| 2 | 应用简介 | 一句话说清业务 | 与官网内容要对得上 |
| 3 | 应用官网 | 能正常打开的完整页面 | 审核员会真的点开看 |
| 4 | 授权回调域 | 纯域名，如 `admin.xxx.com` | 安全闸门，见下 |
| 5 | 应用图标 | 清晰 logo | — |
| 6 | 提交审核 | 约 7 个工作日 | — |

**授权回调域为什么是关键**：扫码确认后，微信只会把登录结果送回这个域名。它是防止别人拿你的 AppID 冒用登录的最后一道闸。所以必须是**你自己的、已备案的纯域名**——不带 `https://`、不带路径、不带端口。

**产出**：审核通过后，应用详情页显示 **AppID** 和 **AppSecret**。

### 阶段四 · 保存密钥（目的：让代码能调通微信）

| 凭证 | 性质 | 放哪 |
|---|---|---|
| AppID | 公开标识 | 前端可以写，出现在 JS 里没关系 |
| AppSecret | 密钥，等同密码 | **只能放服务端**，用环境变量注入 |

AppSecret 只显示一次，关掉页面就看不到了，丢了只能重置。**绝对不能提交进代码仓库**——泄露等于别人能用你的身份调微信接口。

### 拿不到什么

只给 `openid` 和 `unionid`。**没有微信号、没有手机号、没有真实昵称头像**（2021 年后统一返回「微信用户」+ 灰头像）。对外不要承诺这些。

## 六、上线前自检

- [ ] 官网页面可正常访问，内容完整
- [ ] 登录页弹窗正常，二维码能渲染
- [ ] 扫码 → 手机确认 → 进后台，全链路通
- [ ] 未绑定微信扫码，跳到绑定页
- [ ] 二维码放置 5 分钟，显示「已失效」，刷新可用
- [ ] 账号密码登录仍然可用
- [ ] `redirect_uri` 与开放平台配置的授权回调域完全一致
- [ ] AppSecret 在服务端环境变量里，代码仓库搜不到
- [ ] 伪造 state 请求回调会被拒绝
- [ ] 重复提交同一个 code，提示「登录已过期」而不是报 500
